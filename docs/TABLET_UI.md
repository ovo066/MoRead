# 平板与可调整窗口的布局

布局按应用窗口的可用宽度选择，不根据设备名称或固定横竖屏判断。字体和按钮保持正常阅读与触控尺寸，增加空间主要用于并排显示相关内容。

## 窗口规则

| 可用宽度 | 根导航 | 内容组织 |
| --- | --- | --- |
| 小于 600 dp | 底部导航 | 单列、逐页进入；输入区避让键盘 |
| 600–839 dp | 96 dp 紧凑导航栏 | 书库按剩余宽度排封面；表单保持适当行宽 |
| 840 dp 及以上 | 224 dp 侧栏 | 分类与详情、会话与消息、封面与资料可并排展示 |

各页面还要检查扣除侧栏后的实际内容宽度。例如统计图表只有在内容区达到 880 dp 时才分两列；阅读开启伴读后，剩余正文区域决定能否显示双页。

## 页面与交互清单

| 使用场景 | 布局与操作 |
| --- | --- |
| 书库、分组、标签、筛选 | 宽屏侧栏提供分类，书籍自适应列数；列表使用开放行；只保留原有视图菜单 |
| 伴读首页 | 左侧角色列表、右侧角色介绍和聊天入口；编辑与新建仍进入同一角色编辑器 |
| 书库聊天、单书聊天 | 常驻会话列表与消息区；消息行宽有上限，输入区跟随键盘；未发送草稿仍受原有切换保护 |
| 阅读中的伴读 | 在正文旁复用同一个聊天会话；较窄的伴读面板不再嵌套会话侧栏；面板内容仍避让稳定的状态栏／切口安全区，沉浸模式切换不使标题跳动 |
| 书籍详情 | 封面、书籍信息和阅读入口在左；进度、笔记、批注与其他资料在右独立滚动 |
| 阅读正文 | 尊重已保存的单页／双页偏好；正文行宽受限；顶部操作使用独立悬浮按钮，不绘制通栏背景；左侧返回／书籍信息，右侧常用操作，窄平板收起书名为详情按钮；章内进度保持紧凑 |
| 目录、大纲、人物、书签 | 从阅读页左侧展开；页签拥有独立滚动、折叠状态，后台刷新保留锚点 |
| 阅读辅助、词典管理、生词本、中英对照、本段译文 | 复用右侧工具面板、固定标题及关闭按钮；辅助页内进入生词本保留返回与页面状态；翻译进度更新不改变滚动锚点 |
| 阅读排版 | 右侧面板中修改，正文保持原尺寸用于预览；可拖动的精细排版卡保持有限宽度 |
| 批注索引、查词、规则、统计明细等长面板 | 共用 `NavigationSheet`：宽屏侧边展开，窄屏固定内容高度的底部弹层；显式关闭、返回、蒙层关闭均保留 |
| 设置、词典管理、生词本、AI 服务、朗读、备份、存储 | 左侧设置分类、右侧既有功能页；深入编辑保留返回；从其他流程进入的共用页面不会误加设置侧栏 |
| 阅读统计 | 概览跨列，日历、趋势等组件按实际空间排成两列；保留用户组件顺序与显隐设置 |
| 听书 | 封面与播放控制分栏；进度、切章、定时、速度继续连接原有播放状态 |
| 角色、模型、字体、图片、导入等编辑或管理页 | 复用有限行宽的页面壳；这些任务保持顺序表单，避免把输入控件拉满整屏 |
| 短操作与确认 | 保留内容宽度受限的菜单、选择器和确认弹窗，不因屏幕变宽扩大按钮或文字 |

## 验证入口

原生 Compose 渲染与交互测试覆盖手机、800 dp 窄平板、900 dp 竖屏、1400 dp 横屏、深浅主题，以及窗口缩窄后的状态。演示截图使用合成书籍、正文与对话，不读取用户内容或调用模型。

`TabletBookshelfVisualTest`、`TabletSettingsVisualTest`、`TabletReaderVisualTest`、`TabletListenVisualTest` 及伴读、统计、详情页视觉测试生成截图。`ReaderKnowledgeVisualTest` 和 `AnnotationNavigationSheetTest` 在真实父弹层内检查滑动边界、快速滑动、页签切换、后台刷新、底边和锚点。

这些是 Robolectric 原生图形环境的验证；真机的系统栏、输入法、触控笔、鼠标与多窗口仍需实机确认。

## 官方参考

- [Apple：Designing for iPadOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados)：根据观看距离、手持或支架、多种输入方式安排信息密度与操作位置，减少不必要的全屏跳转。
- [Apple WWDC25：Elevate the design of your iPad app](https://developer.apple.com/videos/play/wwdc2025/208/)：导航、可调整窗口、指针与菜单栏的系统教学；导航从 1:25 开始，窗口从 4:58 开始。
- [Android：Canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)：列表与详情、信息流、辅助面板三种组织方式。伴读会话、书籍资料与阅读辅助内容分别对应这些使用场景。
- [Android：Use window size classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)：按实际可用窗口尺寸响应布局变化，不能把“平板”当作固定大小。

以上用于理解交互与空间组织；本文中的栏宽、行宽及断点组合是 MoRead 的具体实现选择。
