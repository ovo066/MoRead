# 书架拖拽排序与合集返回设计

## 目标

在既有独立合集系统上完成四项体验修正：书籍封面可原尺寸拖动并持久调整书架顺序；封面中心重叠仍用于新建或加入合集；拖到书架视口整体高度的上/下 10% 时自动滚动；合集可在显示第一帧立即关闭，并在合集内书籍详情返回后恢复原合集。书架筛选菜单同时提供“阅读后自动前移”开关，默认开启。

## 约束

- 合集继续独立于书架分组，不复用分组表或分组管理界面。
- Android 8.0 及以上行为保持可用。
- 不增加依赖，不升级 Room schema，不增加数据库迁移。
- UI 只复用现有封面、主题色、圆角、图标按钮和 Material3 弹层；参考图只描述交互，不复制其视觉样式。
- Ponytail `full`：优先复用 `ShelfCollectionDragState`、`ShelfEntry`、`ReaderSettingsRepository` 和现有合集接口；不增加通用拖拽框架、导航参数协议或额外状态层。
- 只测试新增的纯排序、落点和边缘阈值逻辑；不增加 Compose UI 测试。
- 不在每个小修改后运行 Gradle。全部代码与静态审查完成后，只运行一次聚焦单元测试与一次 `performance` 压缩 APK 构建；可合并为同一次 Gradle 调用。

## 交互设计

### 1. 原尺寸封面拖动

长按一本未处于合集内的书后：

1. 记录该书封面在根布局中的矩形，而不是整张书籍卡片的矩形。
2. 原书籍卡片保持占位但透明，避免屏幕上同时出现原封面和缩小复制品。
3. 根布局浮层绘制同一 `CompactBookArtwork`，尺寸与记录的封面矩形完全相同。
4. 浮层按手势位移平移，起拖瞬间不跳到手指中心；无论用户按住封面、书名还是列表卡片的其他区域，封面都从原位置自然抬起。
5. 排序落点出现时，列表使用相同 `ShelfEntry` key 临时重排：源书的透明占位移动到候选槽位，其他书实时让位。中心合并落点不做排序预览。

网格和列表共用一套状态；网格以水平方向判断前后，列表以垂直方向判断前后。

### 2. 落点语义

命中目标封面/合集封面的有效矩形后，按主轴比例分为三段：

- 前 25%：`BEFORE`，源书移动到目标之前。
- 中间 50%：`MERGE`。
  - 目标为单书：进入现有“新建合集”命名对话框。
  - 目标为合集：直接加入该合集。
- 后 25%：`AFTER`，源书移动到目标之后。

目标为合集时，`BEFORE` / `AFTER` 将整个合集视为一个书架槽位；合集成员仍按已有 `collectionOrder` 展示。`MERGE` 成功时，源书在持久书架顺序中先移动到目标槽位之后，因此新合集或扩展后的合集留在目标位置。新建合集命名被取消时，不写入这次候选顺序。

### 3. 持久书架顺序

`ReaderSettings` 新增 `shelfBookOrder: List<Long>`，使用一个逗号分隔的 Preferences 字符串保存书籍 ID。该设置只记录顺序，不复制书籍或合集数据。

顺序规则：

- 从未手动拖动时，继续使用当前“置顶时间、最近阅读时间、导入时间”排序，升级后书架外观不变。
- 第一次有效拖动后保存当前全量书籍 ID 顺序，以及当时所有书籍中最大的 `lastReadAt`，作为阅读顺序锚点。
- 新导入但尚未出现在保存顺序中的书籍，按原动态规则排在已保存顺序之前，保证新书可见。
- 删除书籍留下的旧 ID 在读取时自然忽略；下一次写入会只保存当前书籍。
- 执行“置顶”时，将本次置顶的书籍（或所选合集成员）按原相对顺序移动到书架最前；取消置顶不额外移动。之后用户仍可再次拖动。
- 在搜索、分组或标签过滤结果内排序时，只交换当前可见书籍所占的全局位置，隐藏书籍保持原槽位。一个可见合集的全部成员作为连续块参与合并。
- `readingOrderAffectsShelf` 默认 `true`，入口位于现有“视图与筛选”菜单，文案为“阅读后自动前移”。
  - 开启时，只有 `lastReadAt` 大于上次手动排序锚点的非置顶书籍，才按最近阅读时间移动到非置顶区最前；这样阅读行为可以改变最终顺序，又不会在拖动松手后立刻恢复旧的阅读排序。
  - 关闭时，阅读时间完全不参与已保存顺序；未建立手动顺序时仅按置顶和导入时间排列。
  - 再次手动拖动会保存屏幕上的最终顺序并把锚点更新到当前最大 `lastReadAt`，从该时刻重新计算后续阅读行为。
  - 置顶书始终位于非置顶书之前；新置顶动作仍将目标移到置顶区首位。

Room 中的 `collectionOrder` 只负责合集内部顺序；DataStore 中的 `shelfBookOrder` 负责总书架顺序，两者职责不重叠。

### 4. 合集内部排序

打开合集后，成员封面也可长按拖动：

1. 复用 `ShelfCollectionDragState`、原尺寸封面浮层、透明源占位、即时让位预览和视口 10%/90% 自动滚动。
2. 合集成员已经处在同一合集内，因此内部拖动没有 `MERGE` 语义；目标封面主轴前 50% 表示放到目标之前，后 50% 表示放到目标之后。
3. 松手后按新列表顺序依次写回现有 `books.collectionOrder`，不修改 `collectionId`，不新增字段或迁移。
4. 普通点击仍打开详情，右上角菜单仍用于移出合集；只有长按并超过现有 touch slop 的拖动才执行排序。
5. 合集内部自动滚动使用成员网格自身的 viewport，不使用总书架 viewport。

## 自动滚动

`ShelfCollectionDragState` 保存当前懒列表视口。边缘判定使用拖动封面矩形与整个书架视口，不再依赖最上/最下可见书籍：

- 拖动封面的顶部进入视口上方 10%（越过从底部向上量的 90% 高度）时，方向为 `-1`。
- 拖动封面的底部进入视口下方 10%（达到从顶部向下量的 90% 高度）时，方向为 `+1`。
- 其他位置为 `0`。

方向非零期间，每个 Compose frame 调用现有 `LazyGridState.scrollBy` 或 `LazyListState.scrollBy`，固定步长为 `12.dp`。到达内容边界、滚动消费量为零时结束当前循环；手指离开边缘后方向立即归零。滚动导致封面重新布局时，注册矩形更新，落点和边缘方向随之重算。

## 合集关闭与详情返回

### 立即关闭

`CollectionContentsSheet` 在标题行增加项目现有风格的关闭图标按钮，点击直接调用外部 `onDismiss`，不等待 `ModalBottomSheet` 的显示动画状态。弹层内容同时注册 `BackHandler(onBack = onDismiss)`，确保系统返回从弹层显示第一帧起就清空外部状态。遮罩点击继续使用 `onDismissRequest`。

### 从详情返回原合集

`BookshelfScreen` 只保存 `rememberSaveable` 的 `openCollectionId: Long?`，每次从最新 `shelfEntries` 派生实际合集对象：

- 点击合集时写入 ID。
- 从合集打开书籍详情时保留 ID，只执行现有 `onOpenBookDetail` 导航。
- 页面返回或系统返回弹出详情目的地后，书架目的地恢复该 ID，并重新展示同一个合集。
- 用户主动关闭合集或确认解散合集时清空 ID。
- 数据暂未加载或合集已消失时不显示弹层，也不在初始空快照阶段主动清空 ID，避免返回过程中的竞态。

不修改 `MoReadApp` 路由、不增加查询参数或 `SavedStateHandle` 协议；现有 `popBackStack` 返回链保持不变。

## 文件职责

- `core/datastore/ReaderSettingsRepository.kt`：编码、读取和写入全局书籍 ID 顺序、阅读锚点与开关。
- `feature/bookshelf/BookCollectionModels.kt`：纯函数实现默认/手动/新阅读排序、可见顺序合并、以合集为块的槽位移动。
- `feature/bookshelf/BookshelfViewModel.kt`：把保存顺序和阅读开关应用到全量书籍，持久化拖动结果，并维持置顶行为。
- `core/database/dao/ShelfOrganizationDao.kt` 与 `core/library/ShelfOrganizationRepository.kt`：复用现有 `setBookCollection`，按成员列表写回连续 `collectionOrder`。
- `feature/bookshelf/ShelfCollectionDrag.kt`：落点三分区、原尺寸拖动几何和视口 10%/90% 边缘阈值。
- `feature/bookshelf/BookshelfScreen.kt`：列表状态、实时槽位预览、自动滚动、落点动作和可保存的合集 ID。
- `feature/bookshelf/BookCollectionComponents.kt`：原尺寸拖动浮层、目标封面注册、关闭按钮和立即返回处理。
- 既有两个 bookshelf 单元测试文件：只覆盖上述纯逻辑。

## 验证

聚焦单元测试必须证明：

1. 开关默认开启；未保存顺序时开启沿用原最近阅读排序、关闭时忽略阅读时间。
2. 保存顺序后，锚点之前的阅读时间不改变顺序，锚点之后的新阅读移到非置顶区前方，新书仍出现在保存序列之前。
3. 在过滤视图中重排只替换可见槽位，隐藏 ID 位置不变。
4. 单书可以移动到单书或合集之前/之后，合集成员保持连续。
5. 合集内部成员可按目标前半/后半持久交换顺序，且不产生合并动作。
6. 网格左右 25% 与列表上下 25% 分别得到 `BEFORE` / `AFTER`，中间 50% 得到 `MERGE`；禁用合并时按 50% 分为前后。
7. 拖动矩形保持原封面尺寸并按手势位移。
8. 拖动矩形只有进入整个视口上方或下方 10% 区域时才返回滚动方向。

最终一次 Gradle 调用运行这两个测试类并生成 `app-performance.apk`。APK 必须来自 `performance` build type，继承 release 的 R8 与资源收缩并使用 debug 签名，便于覆盖安装现有开发包。

## 验收标准

- 长按拖动显示一张与原封面同尺寸、从原位置移动的封面，原位置没有重复封面。
- 拖到目标中央可创建或加入合集；拖到前/后区可持久重排，重启应用后顺序不变。
- 排序预览中周围书籍即时让位；合集作为一个槽位移动。
- 在书架视口上方/下方 10% 触发区持续拖动可以到达当前屏幕外的书籍。
- “视图与筛选”菜单可开关“阅读后自动前移”，默认开启；开关关闭后新阅读不再改变手动顺序。
- 合集刚显示便可由关闭按钮、系统返回或遮罩点击关闭。
- 从合集内书籍详情返回时，同一合集仍展开。
- 合集内部可长按成员封面调整顺序，重开合集和重启应用后顺序保持。
- 最终交付经过 R8/资源收缩的可安装 APK、文件大小和 SHA-256。

## 非目标

- 不让合集本身成为拖动源。
- 不增加跨设备同步、撤销栈、自定义滚动速度设置或复杂拖拽动画。
- 不改合集视觉样式、分组系统、繁简转换或阅读器导航。
